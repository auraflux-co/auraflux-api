## Task 4 — Gap #32: Gate 3 `clipsExpectedButMissing` behavior on NBA

### Context

Fix 3's `clipsExpectedButMissing` check at Gate 3 is designed to hard-fail when `clipCount > 0` but Gemini doesn't see clips in the assembled video. For News, `clipCount === 0` until clip scraping ships, so the check is silent. For NBA, `clipCount > 0` should always be true (clips come from ESPN scraper). The question: how does Gemini's vision model classify NBA's voiceover-mixed clips?

The VectCut voiceover from Wave 3 produces a clip where:
- Video is ESPN highlight footage
- Audio is Bobby G's narration + background music (clip native audio muted)
- Avatar is NOT on screen during the clip playback

From Gemini's POV: "non-avatar footage playing with narration audio over it." The question is whether Gemini checks the SOURCE CLIPS checklist item as PASS (clip visible) or FAIL (no non-avatar footage — might get confused by the voiceover audio making it think the avatar is still talking).

### Task

Read the Gate 3 why-doc after the NBA smoke test:
```bash
cat output/qa_failures/gate3_assembly_pass_*.txt | tail -100
```

Find the SOURCE CLIPS checklist line for EARLY / MIDDLE samples. Three possible outcomes:

- **SOURCE CLIPS: PASS** — Gemini correctly identifies the ESPN highlight video as non-avatar footage, check works for NBA. Gap #32 resolved.
- **SOURCE CLIPS: FAIL** — Gemini misclassifies the clip. `clipsExpectedButMissing` fires, Gate 3 hard-fails. **Real bug.** Fix: update the Gate 3 prompt at `server.js:~1541` to better describe the voiceover-mixed NBA clip. Example: "SOURCE CLIPS: Do you see any non-avatar video footage playing? For NBA: game action highlights with play-by-play narration audio count as source clips."
- **SOURCE CLIPS: NOT_APPLICABLE** — Gemini couldn't determine. Less common but possible. Prompt may need tightening.

### Outcome routing

- **PASS:** resolved, no action.
- **FAIL or NOT_APPLICABLE:** small Gate 3 prompt wording update. Single commit.
